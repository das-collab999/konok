# Конок — техзадание для разработки

Платформа бронирования юртовых лагерей и гостевых домов Кыргызстана в этностиле.
Туристы находят и бронируют места; хозяева из сёл получают брони в Telegram.

В папке `design/` лежат первые макеты:
- `design/Main.dc.html` — сайт: главная, фильтры, страница места, бронь, оплата, подтверждение;
- `design/HostBot.dc.html` — как хозяин получает бронь в мессенджере.

Из них берём **структуру экранов, тексты и логику**, но не внешний вид: оформление переделано
в спокойный интерфейс без этно-раскраски и рисунков (см. «Дизайн-токены» ниже).

## Как запустить

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # статический сайт в папке out/
```

Важно: папку `out/` нельзя просто открыть двойным щелчком — страницы ищут стили по адресу `/_next/...`,
и при открытии файлом они не находятся (именно поэтому сайт выглядел «голым текстом»).
Сайт нужно открывать либо через `npm run dev`, либо по ссылке опубликованного сайта.

## Как опубликовать сайт по ссылке

Один раз в настройках репозитория: **Settings → Pages → Source: GitHub Actions**.

Дальше при каждом изменении в ветке `main` сайт пересобирается сам
(файл `.github/workflows/pages.yml`) и открывается по адресу:

```
https://das-collab999.github.io/konok/
```

## Где что лежит

- `src/data/places.ts` — тестовые места, доп. услуги, расчёт цены;
- `src/lib/i18n.tsx` — тексты интерфейса на ru / en / zh;
- `src/lib/useBooking.ts` — параметры брони в адресе страницы и формат дат;
- `src/components/` — шапка, подвал, карточка места, иконки, пейзажи вместо фото;
- `src/app/` — страницы: `/`, `/place/[slug]/`, `/place/[slug]/pay/`, `/place/[slug]/done/`, `/bookings/`, `/hosts/`;
- `src/app/globals.css` — цвета, шрифт и базовые стили в одном месте.

## Как заменить картинки на настоящие фото

Пока у места нет фотографии, рисуется приглушённый горный пейзаж (`PlaceArt` в `src/components/ui.tsx`).
Чтобы поставить фото, добавьте полю места ссылку:

```ts
{ slug: "sonkul-aseke", photo: "/photos/sonkul-1.jpg", ... }
```

Файл положите в папку `public/photos/`. Всё остальное подхватится само.

## 3. Роли

- **Турист** — ищет, бронирует, платит, видит свои брони (в т. ч. офлайн).
- **Хозяин** — профиль места, календарь, цены, фото; принимает брони через Telegram-бот или личный кабинет.
- **Админ (основатель)** — проверяет и публикует места, ставит метку «Проверено Конок», видит все брони и выплаты.

## 4. Модель данных (черновик)

- `places`: id, slug, type (yurt | house), title, region (issyk | naryn | chui | jalal | osh | talas | batken), place_name, lat, lng, altitude_m, price_per_person_usd, meals_included, has_stove, has_bath, has_signal, car_access (car | 4x4), toilet, wash, sleeping, road_description, host_story, season_from, season_to, capacity, verified, published, host_id
- `place_photos`: id, place_id, url, sort
- `place_translations`: place_id, lang, title, short, host_story, road_description
- `hosts`: id, family_name, phone, telegram_chat_id, payout_method, payout_details, language
- `extras`: id, place_id (null = общий), title, price_usd, per (trip | guest)
- `availability`: place_id, date, spots_left
- `bookings`: id, code (KNK-xxxxx), place_id, guest_name, guest_phone, guest_email, check_in, nights, guests, extras (json), total_usd, commission_usd, status (pending | confirmed | declined | cancelled | completed), payment_status, created_at
- `reviews`: id, booking_id, rating, text, lang (только после завершённой брони)

## 5. Экраны и функции MVP

### Турист
1. **Главная** — герой с поиском (регион, дата, гости), фильтры-чипы по региону и быту (печка, баня/душ, связь, обычная машина), сетка карточек, блок «Впечатления», блок «Для хозяев». Как в макете.
2. **Каталог + карта** — переключатель «Список / Карта».
3. **Страница места** — галерея фото, «История семьи», «Честно о быте» (высота, туалет, помыться, связь, дорога, отопление, питание, спальные места), «Как добраться», карточка брони: ночи, гости, доп. услуги, расчёт итога.
4. **Оплата** — имя, телефон/WhatsApp, email, способ оплаты.
5. **Подтверждение** — номер брони, анимация тундука, сохранение брони офлайн.
6. **Мои брони** — по номеру брони + телефону (без обязательной регистрации).

### Хозяин
1. **Telegram-бот** (на кыргызском, вторым языком — русский):
   - уведомление о новой брони с кнопками «Кабыл алам» / «Жок»;
   - напоминание за день до заезда;
   - команды: Календарь, Баалар (цены), Сүрөт кошуу (фото), Акчам (выплаты).
2. **Простой кабинет на сайте** — то же самое, для тех, кому удобнее с телефона в браузере.

### Админ
- список мест на проверку, публикация, метка «Проверено»;
- все брони и их статусы, сумма комиссий и выплат хозяевам.

## 6. Правила бронирования

- Цена = цена за чел./ночь × ночи × гости + доп. услуги (trip — за поездку, guest — за каждого).
- Комиссия платформы — 12% (настраивается).
- Хозяин должен ответить в течение 2 часов; если не ответил — бронь уходит админу.
- Бесплатная отмена за 7 дней до заезда (настраивается).

## 7. Оплата

На первом этапе — **режим без реального списания**: бронь создаётся, оплата отмечается админом вручную (перевод / оплата на месте). Код оплаты сделать через отдельный модуль, чтобы позже подключить:
- банковский эквайринг Visa/Mastercard (договор с банком в КР);
- Элсом, MBank (по их API после договора).

Не хранить данные карт на своей стороне.

## 8. Тексты и языки

- Интерфейс: ru, en, zh; кабинет и бот хозяина: ky, ru.
- Кыргызские слова в дизайне оставить как есть: «Кош келиңиз!», «Рахмат! Сизди күтөбүз.», «Үй ээлерине».
- Описания мест хранить по языкам в `place_translations`.

## 9. Порядок работы

1. Создать проект, настроить Tailwind с токенами из п. 2, шрифты.
2. Свёрстать главную и страницу места по `design/Main.dc.html` на тестовых данных (7 мест из макета — это примеры).
3. Подключить Supabase: таблицы из п. 4, тестовые данные, вход для хозяина и админа.
4. Бронь и расчёт итога, страница подтверждения, «Мои брони».
5. Telegram-бот для хозяев.
6. Админка.
7. Переводы, карта, PWA с офлайн-доступом.
8. Деплой на Vercel.

После каждого шага — показать результат и коротко объяснить, что сделано. Объяснять простым языком: основатель не профессиональный программист.

## 10. Не делать в MVP

Мобильные приложения для App Store / Google Play, программу лояльности, чат турист–хозяин внутри сайта, продажу ремесла (это следующий этап).
